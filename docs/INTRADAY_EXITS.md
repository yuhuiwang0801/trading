# V2 盘中退出规则

本次开发为 V2 增加盘中退出，保留原来的日线选股、基本面过滤及开盘买入窗口。本文描述开发版本的规则和运行边界，不表示已经部署到正在运行的实盘服务。

## 时间与触发条件

新买入仍仅在下一交易日美东 **09:35–09:40** 评估。盘中保护在常规交易时段 **09:30 至正常收盘前** 检查，通常随市场 worker 每约 30 秒巡检；半日市使用交易所日历的实际收盘时间。巡检不是逐笔行情订阅，短暂的价格穿越可能发生在两轮检查之间。

盘中规则由独立的 `config/reversal_intraday_v1.json` 定义，版本为 `v2_intraday_exit_v1`，并纳入实盘策略授权哈希。原 `config/reversal_research_v2.json` 继续作为日线研究参数，不为盘中策略改写历史实验口径。

| 规则 | 当前阈值 | 触发依据 |
| --- | --- | --- |
| 绝对价格止损 | 相对真实成交成本亏损 5% | 当前经双源核验的可卖报价 |
| 相对恶化退出 | 累计相对对数收益 ≤ 负的入场偏离 | 完整日线相对路径，加当日股票和冻结同行篮子的相对收益 |
| 盈利回撤保护 | 盈利达到 2% 后，较已验证最高可卖报价回撤 1.5% | 只保存通过核验的持仓峰值；触发资格开启后不因价格回落取消 |
| 反弹修复退出 | 修复入场冻结偏离的 80% | 与相对恶化退出相同的收益口径 |

同一轮同时满足多项时，依次优先记录绝对止损、相对恶化、盈利回撤、反弹修复。首次有效退出原因锁存，后续轮询不能将其改回持有。原有基本面风险、日线退出和最长持有期限仍保留；已经由日线规则锁存的退出保持 **09:35 起** 执行的原有时间语义。

这些阈值描述触发条件，不保证最终成交收益。尤其是 2% 的盈利启动条件和 1.5% 的峰值回撤，并不保证卖出时仍盈利。

## 价格与同行依据

个股触发和峰值只使用通过 Alpaca/Robinhood 双源检查的当前可卖价格。行情必须符合时效、买卖价差、证券身份及可交易状态要求；盘中行情最长允许 30 秒。无效报价不会更新峰值或制造新退出信号。

相对修复以原入场偏离为固定目标。计算使用：

`截至前一完整交易日的累计相对对数收益 + ln(当前可卖价 / 前收盘价) − ln(1 + 冻结同行篮子当日收益)`

当日同行篮子在每日信号包中冻结，用有效同行报价中点相对各自前收盘计算收益；不会因某些同行缺报价而缩小篮子。当前实现还检查各报价的时间对齐。每次巡检从完整日线路径重新计算当日增量，不把相邻轮询的收益反复累加。

同行资料缺失、时间不齐或日线相对路径不完整时，相对修复和相对恶化判断暂停。只要个股价格基准已确认，独立的绝对价格止损和盈利回撤保护仍可检查。

## 公司行动与缺失数据

拆股、分红或其他相关公司行动可能使当前原始价格无法直接与成交成本、前收盘和既存峰值比较。发现相关行动，或行动查询不可用时，不猜测调整因子或现金权益，新价格触发会暂停，等待可验证的基准。

公司行动服务自身可能存在披露延迟或覆盖不全；成功查询为空也不是“绝无公司行动”的保证。盘中绝对价格收益不宣称等于包含股息权益的总回报。原有已锁存退出不会因为缺少新的行情证据而被删除，但实际提交仍必须通过执行校验。

## 执行与上线

退出继续走现有单一订单意图和成交账本。有效触发后提交限价卖单，数量受已确认系统持仓和券商可卖数量限制；买入预算不会阻止已有持仓退出。部分成交、撤单与重试依赖真实券商状态；未知订单结果不能被当作未成交后重复提交，提交订单也不能被当作已经成交。

本地后台离线、电脑睡眠、停牌、网络中断或报价失效，都可能使保护无法及时执行。没有在券商预先托管保证成交的止损单。启用盘中检查也不消除跳空或流动性风险。

开发副本与当前运行目录分开。完成测试后部署需要升级 API 和 worker；策略版本或授权哈希发生变化时，不沿用旧实盘授权。服务重启后必须由用户在页面重新检查并开启实盘；部署脚本或测试不替用户开启交易。

## 外部仓库与验证范围

`auto-trading-bot` 的均值回归思路已单独评审，详见 [外部策略评审](EXTERNAL_STRATEGY_REVIEW.md)。其中的 SMA20、ADX 和 ATR 本轮仅作为后续研究候选，没有启用为新的买卖条件，也没有复制外部执行器、账户配置或自动调参流程。

原页面的历史收益仍属于 V2 日线研究，不能用于声称盘中版本的收益提升或风险下降。盘中版需要使用带正确时间戳的历史行情和公司行动依据，模拟报价时效、成交成本、限价成交、资金占用和断线情形。单元测试和模拟账户场景验证程序行为，不能替代这种历史收益验证，也不能证明实盘一定及时成交。
