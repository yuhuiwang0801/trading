# 策略、订单和账本规则

## 筛选和信号

默认趋势突破参数保存在版本化 settings 中，变更追加 before/after 审计。日线源使用 raw 价格口径；只读取上一交易日及更早的完整数据。ATR14 当前定义为最近 14 个真实波幅的算术平均，非 Wilder 平滑，版本固定。

候选要求至少 120 个完整交易日、前收盘不低于 $5、20 日日均成交额不低于 $20M、close > MA20 > MA60；60 日涨幅降序取前 30。默认真实接口可配置扫描股票范围，未指定时使用数据源当前有效证券列表；证券类型用保守名称过滤，尚不替代专业证券主数据。SPY 前收盘高于 MA60 才允许买入。

突破使用此前 20 个完整日线的最高价。已完成的相邻 5 分钟收盘从 ≤ 阈值变为 > 阈值才形成新信号。单股票、单账户、单日只生成一次买入信号；在 TTL 内，行情恢复等情况可以重新评估尚未执行的同一信号；忽略或失效后当日不重新触发。次一交易日可以重新判断。默认信号/订单 TTL 为 300 秒。

退出依据入场时 ATR：初始保护 = 成交均价 − 2 ATR；移动保护 = 持仓以来已完成 5 分钟最高收盘 − 3 ATR。保护只上调。逐个处理尚未检查的已完成 K 线，避免把新保护线追溯应用到旧 K 线。收盘跌破保护或上一交易日 MA20，形成卖出信号。只对 managed 持仓自动退出；纳入已有持仓必须提供 ATR 与 MA20。

**保护规则运行在本地 worker，并不是券商端止损订单。** 程序停止、系统睡眠或行情失效都可能阻止本地保护执行。退出信号不是成交承诺；限价卖出也可能无法成交。

## 风控与资金

默认权益 $10,000、每股仓位上限 10%、总敞口 60%、最多 6 股、每笔风险 0.5%。数量由风险预算/止损距离确定，再受整股、单笔金额、当日新增额度、现金、费用与仓位上限约束。候选统一排名并依次持久化占用，后续候选使用扣除前序占用的可用额度。

现金账户模拟 T+1 交易所工作日结算。已收回现金、已结算现金、资金占用和购买力分别显示。不模拟融资，不写死 PDT 阈值。真实账户规则必须在第二阶段根据券商权限和限制适配。

报价必须双边有效、非未来、未过期且价差符合阈值。数据质量异常阻止新指令；已有订单仍保留并同步。暂停新开仓继续退出；停止全部提交保留监控和同步；紧急停机还请求撤销本系统订单，既不默认清仓也不撤销手工订单。

## 订单状态

`PENDING_SUBMIT → SUBMITTING → ACCEPTED / PENDING_APPROVAL / UNKNOWN / REJECTED`，随后可进入 `PARTIALLY_FILLED / FILLED / CANCEL_PENDING / CANCELLED / EXPIRED`。内部确切审批枚举见 `paper.py`；真实枚举必须在发现 schema 后映射。

Signal、OrderIntent、BrokerOrder、Fill、Position 分别存储。稳定意图 ID 和资金占用在网络提交前提交数据库事务。订单状态不能直接改持仓，只有去重后的已核验成交改变现金和持仓。

提交超时进入 UNKNOWN，保留占用，先用可靠标识查单。无法确认时阻断新增风险并保留审计。重启先恢复 SUBMITTING/UNKNOWN，未开始提交的遗留意图安全取消，不自动重发。数据库唯一键只保证本地去重，不宣称保证券商只执行一次。

撤单先进入 CANCEL_PENDING，确认前仍接受有效成交。仅在终态确认后释放未成交部分。重复成交按 broker_fill_id 去重；不同 ID 的延迟成交可在撤单后补记且不恢复已释放占用。

## 模拟成交规则

- 买入限价默认 ask + 5bps，卖出限价 bid − 5bps，按 $0.01 价格步长处理。
- 订单接受时不成交，必须看到 timestamp 严格晚于 submitted_at 的报价。
- 默认买入 ask + 2bps 滑点、卖出 bid − 2bps 滑点，且不能穿越限价。
- 默认费用 1bps；数量不超过输入报价关联成交量的 1%，并受买卖盘可见量（如提供）约束。同一报价不被重复消费。
- 报价、价差、TTL 和交易时段共同约束撮合。不会仅因 K 线触价就认定全额成交。
- 这是软件模拟模型，无法复现真实队列优先级、跨市场深度、停牌成交或券商规则。真实行情回放结果不构成可成交保证。

## 审计与对账边界

业务、决策、系统事件追加写入。每条成交能关联 order → intent → signal → run，并保留触发值、规则、数据时间、前后现金/持仓。ORM 拒绝修改与删除已有审计；数据库管理员仍具备底层权限，因此生产须配置只追加权限、备份与外部归档。

模拟对账能检测外部持仓、余额和订单差异并暂停新增风险，保留差异证据。**任意券商手工交易的自动入账、公司行为记账及真实账户镜像同步尚待第二阶段实现**；不会通过覆盖历史账本隐藏差异。
