# 实盘启用与运行

## 当前结果

2026-10-27 已完成独立 OAuth、87 个真实 MCP 工具发现和专用账户七项只读核验。经用户指定，真实券商预览 **买入 F 1 股，限价 $11.62**（查询时返回的卖价）结果 `READY`，无预检警告，该样例不要求审批。

后台实盘策略、独立账本、提交/撤单适配、审批关联、成交对账与重启恢复已实现，写流程通过模拟券商响应测试。**本次真实下单、撤单、审批操作均为 0**。真实资金成交、实际撤单最终确认、长期 OAuth 续期和开市后的 IEX 报价时效仍待实证。

实盘由设置页按钮启停，默认关闭，本次未代用户启用。概览、持仓、订单、信号及日志显示独立实盘数据。券商已有持仓可查看，但不自动接管；无法确定的市值或盈亏显示未知，不使用模拟数据或零值替代。选股仍基于 Alpaca 行情，模拟和合成回放保留在隔离的后台研究流程。

## 如何开启（本次未执行）

1. 打开 `http://127.0.0.1:8010/#settings`，「实盘自动交易」直接显示 V2，无需选择策略。
2. 点击「开启实盘」。平台自动检查真实账户，并按 V2 规则生成股票范围、单笔及每日金额、最多持仓。检查通过后，核对自动生成的摘要，完成一次**使用真实资金的确认**。

用户不需要填写股票或额度。V2 自动使用经过身份核验的 190 只股票池，单证券/发行人上限为当前账户净值的 5%，行业 25%，每日新增买入 20%，最多 20 个持仓、每日最多 4 个新入场。实际买入进一步受可用现金、未完成委托预留、现有持仓和整股数量限制。原「趋势突破」策略及其演示、回测入口已下架，历史记录和底层研究模块保留。

美元额度随最新券商账户净值计算，确认的是策略比例与规则，页面上的美元数值是当前快照，不是永久固定金额。策略规则或股票池身份发生变化会要求重新检查和确认。持仓数及敞口限制包含外部已有仓位，但不接管其卖出。首次使用或授权失效时，先通过「连接账户」在 Robinhood 官方页面完成授权；正常使用无需单独刷新账户或保存范围，平台已移除手动订单预览功能。

设置页和确认弹窗按最新完整日线收盘价估算当前候选是否买得起 1 整股，计入限价偏移和费用预留。预算不足时说明具体原因，不擅自提高仓位比例或改用零股，也不阻止开启后等待未来合格信号。这只是价格与预算参考；实际下单仍需最新盘口及全部风控通过。

首次正式启用前，如果本账本从未创建任何自动交易意图、订单、成交或持仓，且当前没有未完成券商订单或待审批事项，平台可在停用状态下按完整的新账户快照重新记录手动交易基线。仅解除对应外部订单/持仓变化标记并留审计；不清除其他异常、不接管持仓。已有任何自动交易历史后，不使用这条首次准备路径处理账本差异。

设置页已移除「行情连接」及「模拟账户控制」面板。Alpaca 策略行情由部署配置继续提供；开启时仍需有效授权、可用行情、在线且版本匹配的交易 worker，以及无待处理异常的账户。检查不通过时按页面原因处理；按钮不能跳过这些条件。

启停不需要修改 `.env` 或重启服务。`ROBINHOOD_LIVE_ENABLED` 已弃用，已有值不会启用或阻止实盘。API 或交易 worker 重启均撤销启用状态，需要再次点击「开启实盘」并确认。

确认启用不代表立即买入。后台只在常规交易时段执行符合策略与风控的信号；**每笔策略委托仍独立检查账户、价格、数量、券商预览与两家盘口**。当前自动策略仅支持整股、多头股票、当日限价、常规交易时段，不自动改成金额单、零股单或市价单。

使用策略自动配置时，参数来自版本化策略规则，不读取旧模拟账户的自定义仓位设置。可用购买力、现有仓位、整股要求及策略风险预算可能使某个信号无法下单；系统不自动降低风控以促成交易。IEX 是单交易所行情，盘中时效仍需持续验证。

## 自动订单预检

手动「订单预览」的页面入口、表单和调用功能已移除，原 `POST /api/live/preview` 返回 `410`，不会再调用券商预览。自动交易内部仍强制执行券商预检、账户与风控检查，以及下方的盘口交叉校验，用户无需手动填写预览参数。自动提交仍只支持整股限价。

此前金额/零股功能已通过真实 schema 和模拟券商响应测试，未代用户选取新参数调用真实券商预览。此前 F 整股限价预览仍是唯一实际订单预览样本。自动策略使用下方盘口交叉校验；预览通过不代表之后的提交校验也会通过。

## 提交前盘口交叉校验

每次自动提交先完成券商预览，再独立读取该股票的 Robinhood 最新盘口。读取不使用缓存，不以昨收或本地接收时间替代场所报价及时间。账户读取完成后、真正发送前再次校验时效，预览、报价读取、审计落盘和账户读取耗时均计入有效期。

- Alpaca 报价时间、Robinhood 买价时间和卖价时间均不得晚于检查时间，年龄上限为 `min(30, quote_max_age_seconds)` 秒；缺失、无效、零价、交叉盘口或不可交易状态均拦截。
- 两家各自买卖价差受 `max_spread_pct` 限制；两家对应买价、卖价的偏差，以及委托限价与 Robinhood 可执行一侧的偏差，受 `max_price_deviation_pct` 限制。当前两个参数默认均为 **0.5%**，实际按已保存策略参数检查。
- 买入还检查新信号的已完成 K 线时间及价格：信号年龄受 `bar_max_age_seconds` 限制，Robinhood 卖价和委托限价相对信号价的偏差也不得超过价格偏差上限。卖出检查当前两家盘口及当前委托限价，不用历史入场价限制退出。
- 系统保留原始限价，不追价、不改成市价。通过校验仍可能挂单而未成交。

明确在发送前被拦截的意图释放本次占用，后续有效行情可重新评估；已经发送但结果为 `UNKNOWN` 的请求继续保留占用和阻断，不能直接重试。详情见设置页「运行详情」中的「盘口交叉校验」：显示最近一次结果以及两家价格、时间、偏差、阈值和原因，历史证据保留在独立账本与审计中。没有记录表示尚未走到该检查，不代表失败，也不增加启用门槛。

这项检查验证当前执行价格与信号的一致性，不改变 Alpaca IEX 策略行情来源，也不证明不同来源的历史 K 线或成交量完全相同。自动策略只使用整股限价，主界面不提供金额或零股预览。

## 停止与恢复

- 「停止实盘」立即写入跨进程停止标记，阻止尚未发出的提交或撤单。它不清仓、不撤销已送达券商的订单，仍继续只读同步已有系统记录；网络途中或已被券商接收的请求无法由本地标记撤回。
- 停止后若要恢复，点击「开启实盘」，通过自动检查并完成真实资金确认。修改旧变量 `ROBINHOOD_LIVE_ENABLED` 不能替代停止按钮。
- 不确定提交 `UNKNOWN`、外部订单/仓位变化、审批被编辑、账户切换或成交不一致会停止自动提交并保留占用。先核对 Robinhood 与本地审计，不能删除实盘数据库来解除阻断。
- 仅管理本系统新建持仓，不接管已有外部持仓。公司行为或手工交易造成无法解释的数量变化时阻断执行，尚未自动解释并调账。
- 本地保护线依赖 worker 在线，不是券商托管止损。停止新提交也停止自动退出提交。

## 执行实现

正式适配器为 `RobinhoodTradingAdapter`；旧通用 `RobinhoodMCPBroker` 保留用于连接状态与工具发现。实际 input/output schema、固定官方端点、固定工具名、语义回显和 Decimal 校验共同约束请求。只为明确不下单的 `review_equity_order` 设置预览例外，不放宽其他工具权限，不执行返回的 `guide`。

`LiveExecutionService` 使用独立 SQLite 账本，默认位于主数据库旁的 `*.robinhood.sqlite3`，权限 `0600`，跨进程锁串行化提交与对账。可用 `ROBINHOOD_LIVE_LEDGER` 指定本机路径；当前面向单机单 worker，不宣称分布式高可用。

生产服务具备实盘适配能力，但实际写入由独立账本中的用户启用状态、跨进程停止标记和每笔提交前检查共同约束。创建服务不代表启用；API 与 worker 启动均撤销此前启用状态。界面显示的启用状态对应实际 `armed` 状态，不再读取旧环境变量。worker 心跳包含控制版本，旧版或过期心跳不能满足按钮启用条件。

意图及 UUID `ref_id` 在真实提交网络请求前落盘。不确定提交不盲重试，通过完整订单分页恢复。审批链保留原始 ref_id、approval_id 与 order id；审批后的新订单可能使用 approval_id 作为 ref_id。批准不等于成交，编辑后的审批阻断自动管理。

成交按 executions.id 去重，累计数量与券商持仓核对。全量分页可以补拉旧订单的新成交。撤单 accepted 只进入待确认状态，部分成交及最终撤单通过后续查询确定。账户原有持仓和历史订单作为未管理基线，无法解释的变化保守阻断。
