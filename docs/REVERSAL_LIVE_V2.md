# V2 平台接入与运行差异

平台仅保留 V2，策略 ID 为 `reversal_v2`。策略规则沿用 `config/reversal_research_v2.json`，其原始文件 SHA-256 同时绑定每日信号包与实盘配置。旧策略 `trend_breakout` 及其演示、回测入口已下架，历史记录和底层研究模块保留。

2026-10-29 起，设置页直接显示 V2，无需选择策略或填写股票范围、额度和持仓条件。`POST /api/live/prepare-strategy` 仅接受 `reversal_v2`，自动核验账户并生成完整 190 只股票池、净值比例额度及持仓上限；不会启用实盘。最后由用户确认真实资金执行。手动订单预览功能已移除，自动交易内部的券商预检保留。原手动范围 API 保留用于旧版兼容，主界面不再要求填写条件。

## 日常流程

- 日线信号使用 Alpaca SIP 历史数据及已披露 SEC 资料，按原 V2 股票池与行业同行计算。自动配置覆盖固定 190 只股票池，每日只买满足候选条件的股票；不再受之前 AAPL 单股测试配置限制。
- 信号对应上一完整交易日，按纽约时间 18:00 的日期切换规则冻结。只有对应下一交易日的有效信号包可以产生新买入。
- 下一交易日 09:35–09:40 ET 允许新买入。每日最多 4 个新入场，最多 20 个持仓，单证券和发行人最多 5%，行业最多 25%，当日新增买入最多 20%。自动配置按当前账户净值换算单笔及每日美元额度，每次执行使用最新有效账户快照，并进一步扣除现金预留与已有敞口。
- 只买整股，使用券商确认的现金与无杠杆购买力，扣除未完成订单的预留。未成交和部分成交订单占用相应额度；重复扫描不重复买入。
- 券商确认成交后，持仓保存实际数量、含成交费用的加权成本、信号日偏离、发行人、行业和持仓期限。进程重启不会重置这些锚点。
- 收盘后判断反弹修复 80%、基本面风险、5% 绝对亏损、相对偏离继续恶化及最长 10 个交易日；触发后从下一交易日 09:35 起尝试卖出。退出原因一旦锁定便保留，当天可继续重试未完成的退出。最长持仓退出独立于最新日线包是否可用。

新买入必须经过现有的账户核验、启用确认、后台执行服务检查、券商预览和 Alpaca/Robinhood 双源报价核验。重启会撤销启用状态，需要重新确认。交易范围中的策略 ID 必须为 `reversal_v2`，并与当前 V2 规则一致。

买入窗口结束不会使已校验日线失效为持仓管理资料。已有管理持仓或未完成指令时，日线更新失败也不阻止用户重新确认启用，以恢复卖出及订单状态处理；这不放宽新买入的数据或时段要求。平台每分钟检查是否需要生成新交易日信号，失败至少间隔 30 分钟再自动尝试，慢任务在独立研究进程执行。

## 与历史回测的差异

研究结果使用次日开盘价近似成交；平台使用实时双源报价生成限价单。价格、成交数量、成交延迟及未成交都会造成收益差异。入场订单的提交有效期最迟到 09:40，已提交订单的取消仍需要券商确认。

原平台 `max_price_deviation_pct` 默认是 **0.005，即 0.5%**。此保护在 V2 中继续生效：买入限价与 Robinhood 卖价要接近日线信号收盘价，同时两家报价及限价之间也必须通过价差核验。因此次日开盘已经偏离昨收超过 0.5% 的候选可能完全不成交，实际交易次数可能显著低于历史回测。接入时没有放宽这个保护。

V2 不使用旧趋势策略的 ATR 仓位算法、突破指标和 60% 总敞口参数。报价新鲜度、最大点差、价格偏离、限价偏移、费用预留和订单时限仍沿用现有执行配置。

相对反转路径与研究版本一致：以信号日冻结的偏离为目标，从信号收盘之后逐日累计股票相对同行的对数收益，包含买入日隔夜段。绝对止损使用总回报复权价格与实际成交成本归一化，是对研究中“原始价格加现金股息”口径的近似。复权序列改变时，调整因子从同一份数据重算，实际成交成本和偏离目标保持不变。

## 数据与持仓边界

日线或基本面资料缺失、陈旧、哈希不一致会阻止新买入。暂时未刷新完成的日线保留回放检查点；明确缺失同行残差时，仅关闭相对修复与相对止损判断，仍允许已知基本面风险、有效价格止损及最长持仓退出。

手动或其他系统的券商持仓计入持仓和行业额度，但不会被 V2 接管或卖出。无法确认其发行人、行业或市场价格时，暂停新买入。历史旧策略持仓和未完成指令不会自动迁移为 V2；存在不兼容记录时，后台阻止重新配置。拆股、手动增减仓等导致券商数量与本地账本不一致，沿用原平台的对账阻断流程，不静默修改持仓。

退出规则在本地后台运行，没有预先托管到券商的保护单。缺少有效报价、账户对账失败或后台离线时，触发记录仍保留，但无法保证及时成交或保证止损价格。

## 主要实现与验证

- `backend/trading/reversal_runtime.py`：每日数据、信号包与有效期。
- `backend/trading/reversal_dispatch.py`：每日信号与实时执行报价衔接。
- `backend/trading/live_reversal.py`：日历窗口、冻结规则与日线退出状态。
- `backend/trading/live_execution.py`：配置、持仓、额度、预览与订单账本。
- `backend/tests/test_live_reversal.py`：使用模拟券商验证窗口边界、重复扫描、部分成交、持仓重启、发行人额度、动态退出、迟到日线及缺数据期限退出；测试不会调用真实券商下单。
